# Dili PWA：多机器入口

PWA 是同一份网页应用，安装到电脑、Android 和 iPhone 主屏幕；不是 APK、EXE 或 IPA，也不需要为每个平台安装 Agent。Agent 仍运行在用户自己的机器上。

## 安装

机器列表提供「安装到桌面」按钮。Chrome / Edge 在浏览器允许时直接弹出安装确认；不支持该接口时显示平台操作指引。iPhone 仍需手动通过 Safari 分享菜单添加。安装后从桌面图标启动，Android 优先请求全屏，iPhone 使用系统提供的独立窗口；系统状态栏和跨域页面不能保证隐藏。旧安装的显示模式由浏览器更新，必要时移除旧图标再安装。

- x86 电脑：Chrome / Edge 打开 HTTPS Dili 地址的 `/#/machines`（中继地址保留 `/connect/d/<设备>/` 前缀），使用地址栏或菜单的「安装应用」。
- Android：Chrome 打开相同地址，菜单「安装应用」/「添加到主屏幕」。
- iPhone：Safari 打开相同地址，分享 →「添加到主屏幕」。
- 首次加载需要联网。HTTPS 是远程安装、Service Worker 和麦克风的前提；localhost 只指访问设备本身，手机连接电脑请使用电脑的 HTTPS 远程地址。

## 连接机器

1. 点 `+ 发现你的机器`，输入 Dili 地址和可选名称。
2. 点「下一步：验证机器」，浏览器打开目标机器；尚未登录时输入该机器所有者密码。
3. 验证成功后自动保存机器卡片并进入联系人，无需手动返回。跨域时会短暂经过入口页以保存当前浏览器的机器列表。
4. 点卡片打开联系人；需要返回时使用工作空间导航内的返回箭头。没有额外的顶部机器导航栏；iPhone 跨域打开时的系统地址栏仍由系统控制。

机器列表只在当前浏览器/安装实例保存，不跨设备同步。移除卡片不会删除机器数据，也不会撤销目标机器的登录；撤销设备授权请在目标机器的安全设置完成。密码不写入列表、URL 或浏览器本地存储，认证沿用机器的 HttpOnly 设备 Cookie。登录过期时需重新登录。

浏览器不能静默扫描局域网，首期「发现」使用手动填写链接。跨域机器会以顶层页面打开，不使用 iframe 或跨域密码代理。操作系统可能将超出安装作用域的地址交给浏览器打开；要尽量保持应用内体验，建议机器都使用同一个 HTTPS 中继站点。即使同站点，独立设备路径仍可能超出当前 PWA 作用域。机器首页和连接操作保持一致，但系统安装提示、权限弹窗和返回手势由平台控制。

## 卡片填写邀请码

机器卡片可直接填写 `SD1.` 开头的中继邀请码，点「转为远程连接」。目标机器完成验证后兑换邀请码、启动中继，连接就绪后自动用远程地址替换卡片并打开联系人。邀请码只在配对期间的内存中使用，不写入卡片或持久化存储；跨域交接使用 URL 片段，并在目标页面渲染和认证前移除。两端均需新版前端。

首次配置必须在运行 Dili 的电脑上，通过本机地址操作；远程页面不能开启、修改机器的远程访问配置。电脑打开自身的机器列表会显示「当前机器」卡片，可直接输入邀请码。需要先设置所有者密码。已启用邀请码中继的机器会复用现有远程地址，不再次消耗邀请码。连接失败可重试或返回，原卡片不会丢失。

纯网页不能执行 UDP/mDNS 局域网发现，HTTPS 公网入口访问 HTTP 内网还受混合内容和本地网络权限限制。本版没有局域网自动扫描；要实现真正的自动发现，需要机器端的发现服务或原生辅助程序，并处理网络权限、防火墙及 WSL 网络隔离，不能用猜测 IP 的浏览器扫描替代。

## 离线与更新

机器列表与公开应用外壳可离线打开，联系人的会话、终端、语音和实际工作需要机器在线。Service Worker 不缓存 API、密码、聊天或附件；不强制刷新正在工作的页面，新版本在下次启动生效。

## 独立部署发布包

`dili-pwa-<版本>-all-platforms.tar.gz` 是三平台共用的静态入口。解压后将目录通过 HTTPS 静态站点部署在域名根目录；配置未知路径回退到 `index.html`，`sw.js` 使用 `Cache-Control: no-cache`。浏览器打开首页就是机器列表。该包不包含 Agent 服务，需连接已运行 Dili 的机器（建议同版本或更新版本以支持配对返回）。不需要运行 npm install 或构建。

## 验收范围

自动化覆盖桌面和两种手机宽度的添加、验证、保存、删除、联系人跳转、返回，以及离线首页和缓存隔离。浏览器模拟不能替代 iPhone/Android 真机安装、麦克风权限、后台恢复和跨域跳转验收；发布前后应在真实设备核对这些系统行为。
